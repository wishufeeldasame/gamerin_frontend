기준일: 2026-10-09
백엔드: develop `6318363896373da4d9b94694a384b0ee94994cf2`

이전 비교 자료는 API 추가 전 상태를 설명한다. 아래 상태는 백엔드의 위 커밋과 이번 프론트 작업트리 변경을 기준으로 갱신한 것이며, 설계 문서 전체의 구현 완료를 의미하지 않는다. 원문 설계 문서 4종을 이번 검증에서 직접 대조하지 못했으므로, 사용자가 제공한 비교 자료와 실제 코드의 계약을 기준으로 구분했다. 원격 저장소의 최신 여부와 실행 중인 백엔드 이미지의 커밋까지 확인한 결과는 아니다.

## 최신 구현 상태

모든 경로는 /api/v1 기준이다. 관리자 API는 ADMIN 권한, 내 신고 API는 로그인한 사용자 권한이 필요하다. 목록 응답은 ApiResponse 안의 Spring Page이며 page는 0부터 시작한다.

인증 구현에는 앞선 계정 전환 버그 수정이 포함된다. auth-store·auth-api·AuthContext에서 사용자 ID 일치 검사, 인증 세대와 탭별 재인증 처리를 보완했으므로 “공통 인증 코드 변경 없음”이라는 이전 표현은 잘못됐다. 메모리 access token·HttpOnly refresh cookie·일반 401의 갱신 후 1회 재시도·401/403 권한 처리 정책과 API 계약은 유지했다. 이번 잔여 문제 수정에서는 공통 인증 코드를 추가 변경하지 않았다. 로그인 사용자 role은 기존 isAdminRole 함수를 사용하여 ADMIN과 ROLE_ADMIN을 동일하게 판별한다.

## 재검토에서 수정한 표시·동기화 문제

- 다른 탭에서 계정이 변경되면 이전 탭의 사용자 상태와 토큰을 비우고 재인증하도록 보완했다. 다른 계정의 토큰으로 내 신고 요청을 재시도하지 않으며, 새 계정 탭의 공유 세션을 로그아웃시키지 않는다.
- 신고 상세 제재의 endAt은 한국어 절대 날짜·시간으로 표시한다. 미래 종료일이 “방금 전”으로 표시되지 않으며, null은 경고·영구정지 등의 유형에 따라 기존 의미를 유지한다.
- 프로그램 검색 안내는 실제 서버 조건인 “제목 · 멘토 닉네임 검색”으로 표시한다. 검색 파라미터와 필터 정책은 유지했다.
- 콘텐츠 복구 완료 시점의 현재 페이지를 재조회하며, 이전 페이지·계정·화면의 늦은 응답을 무시한다.
- 대시보드는 “처리 완료 상태 신고”, “현재 처리 완료 상태인 신고 수”로 표시한다. 현재 RESOLVED 수는 재검토로 줄어들 수 있으므로 누적 집계라고 안내하지 않는다.
- 신고 목록은 PATCH 성공 응답을 mapper로 변환해 해당 행에 반영한다. 활성 상태 필터에 맞지 않으면 행만 제외하고, 총 건수·정렬·페이지는 추정하지 않는다. 후속 GET 실패 시 성공 상태를 되돌리지 않고 해당 UUID만 추가 변경을 막으며, 집계는 마지막 조회 기준임을 안내한다.
- 후속 GET이 지연돼도 다른 신고는 PATCH 완료 후 변경할 수 있다. 마지막 PATCH 성공 이후 시작한 현재 조회 조건의 GET이 실제 반영될 때만 재조회 대기 잠금이 해제된다. 늦은 GET·페이지 축소·연속 이벤트·화면 종료·관리자 전환을 보호하고, PATCH 실패나 새로고침에 자동 재제출하지 않는다. HTTP 계약은 유지하고 선택적 AbortSignal만 추가했다.

## 실제 연동 미검증 및 백엔드 확인 필요

아직 운영·공유 데이터와 분리된 백엔드 테스트 환경 및 계정이 확인되지 않아 실제 API로 제재·숨김·설정 변경을 실행하지 않았다. 실행 중인 백엔드 이미지에 커밋 정보가 없어 위 기준 커밋인지 확인하지 못했다. 기존 스택의 미인증 API 401 검사는 이전 검토 기록이며, 이번 mock 테스트를 실제 백엔드 검증으로 취급하지 않는다.

이번 검증에서 기존 서비스·DB·볼륨을 변경하지 않았다. 소유 라벨과 외부 mount 없음이 확인된 검증용 컨테이너만 종료·제거했으며, 다시 생성 가능한 이미지 fixture와 임시 Playwright 설정도 정리했다. 테스트 이미지는 gamerin-admin-api-verify:20261009와 gamerin-frontend-admin-residual:20261009로 남겼다. 커밋·푸시·머지·실제 배포는 수행하지 않았다.

- [ ] 전용 테스트 환경에서 실제 신고 상세·검토·통합 판정과 사용자 제재·해제·감사 로그 반영.
- [ ] 실제 관리자 보호 HTTP 400과 판정 트랜잭션 롤백.
- [ ] 실제 SUSPENSION_3D의 시작·종료 시각과 계정 상태.
- [ ] 서로 다른 일반 사용자 두 계정의 /reports/my 격리와 관리자 API 접근 거절.
- [ ] 실제 멘토 승인·사유 필수 반려·프로그램 상태·숨김 및 설정 저장/재조회.

별도 백엔드 확인 사항:

1. MENTORING 신고 targetId는 신청 UUID인데 프로그램 reports 집계는 프로그램 UUID를 조회한다. 신고 수 열은 숨겼으며, 집계 수정은 백엔드 팀 확인 사항이다. 외부 메시지나 이슈를 자동 발송하지 않았다.
2. 신고로 숨긴 게시글도 기존 soft-delete 정리 대상이며 원본·미디어가 영구삭제될 수 있다. 무기한 복구를 약속하지 않는다. 실제 운영 정리 기간은 확인하지 않았다.
3. 종결 신고의 단순 PATCH/start-review 재개 가능 여부는 현재 서버 동작을 유지한다. 새 상태 전이 정책을 프론트에서 만들지 않았다.
